# bio-site — сайт-визитка команды HumsterStudio

Одностраничник на чистом коде: **HTML + CSS + ванильный JS, без фреймворков, сборщиков
и внешних библиотек**. Тёмно-серый минимализм, живой фон с анимированной волной, плавный скролл,
«стретч»-эффекты и кастомный курсор (круг + динамические точки в центре).

## Файлы

Версия одна, но в двух видах: **модульная** (править код) и **одним файлом** (отправить,
залить, открыть где угодно). Обе показывают один и тот же сайт.

Модульная версия — то, с чем работают:

| Файл | Размер | Что внутри |
|---|---|---|
| `index.html` | ~15 КБ | семантичная разметка: фон, hero, услуги, работы, команда, процесс, контакты |
| `styles.css` | ~33 КБ | 20 нумерованных разделов: токены, база, секции, адаптив |
| `script.js` | ~45 КБ | 11 нумерованных разделов: CONFIG, рендер, скролл, кадр, фон, курсор |
| `assets/bg-main.jpg` | ~54 КБ | фон сайта: тёмный абстрактный, 1920×1080 |
| `assets/logo-mark.png` | ~3 КБ | знак для шапки: круг со «звездой», 128×128, прозрачный фон |
| `assets/logo-emblem.webp` | ~48 КБ | эмблема целиком для секции «О команде», 320×320, прозрачный фон |
| `assets/logo-hs.webp` | ~13 КБ | оранжевая монограмма HS для подвала, 220×170 |
| `assets/favicon.png` | ~1 КБ | иконка вкладки, 64×64 |
| `standalone.html` | ~267 КБ | **всё то же самое в одном файле**: готовый контент в разметке, CSS и JS внутри, все картинки в base64 |
| `tools/build-standalone.js` | ~10 КБ | сборщик `standalone.html` из модульной версии |

Модульная версия весит ~180 КБ (из них ~120 КБ — картинки) и открывается двойным кликом
по `index.html`.

### Логотип: три места

Бренд стоит в трёх местах — так, чтобы и в шапке читался, и целиком был виден:

| Где | Что | Размер |
|---|---|---|
| Шапка | `logo-mark.png` — знак «круг со звездой» из логотипа, слева от названия | 26×26 |
| Секция «О команде» | `logo-emblem.webp` — вся эмблема с рабочим местом, надписью и ролями | до 200 px, справа в заголовке секции |
| Подвал | `logo-hs.webp` — оранжевая монограмма HS | 30 px по ширине |

Все три вырезаны из твоих файлов с прозрачным фоном: у картинок фон был почти чёрным,
поэтому он снят по яркости, тонкие линии обводки слегка утолщены (иначе на 26 px знак
выцветал), а лишний мусор по краям убран круглой маской.

Эмблема и монограмма сохранены в **WebP**: та же картинка в PNG весила 190 КБ и 37 КБ
против 48 КБ и 13 КБ. Если понадобится PNG (например, для печати или рассылки) — скажу,
как пересобрать.

Заменить любой из знаков: положи свой файл в `assets/`, поправь путь в `index.html`
(`.brand__mark`, `.about__emblem`, `.footer__mark` и `<link rel="icon">`) — сборщик
подставит его в однофайловую версию автоматически, форматы png/jpg/webp он понимает.

### Пересобрать однофайловую версию

После правок контента в `CONFIG` (или стилей) запусти из папки `bio-site`:

```powershell
node tools/build-standalone.js
```

Скрипт подставит свежую разметку, стили, скрипт и фото в `standalone.html` и сразу
напечатает самопроверку: совпадают ли встроенные стили и скрипт с исходниками побайтно,
нет ли внешних ссылок, на месте ли контент. Если что-то не так — он скажет об этом,
а не молча соберёт сломанный файл.

### Когда какой вид использовать

* **`index.html` + `styles.css` + `script.js`** — для работы: правки контента в `CONFIG`,
  стили отдельно, браузер кэширует файлы, искать по коду удобно.
* **`standalone.html`** — когда нужно отправить сайт одним файлом, положить на флешку,
  залить на хостинг одним действием или показать заказчику без архива. Внешних запросов
  ноль: ни шрифтов, ни картинок по сети. Контент в нём уже вписан в разметку, поэтому
  страница читается даже с выключенным JavaScript — скрипт только добавляет эффекты.

Собирается `standalone.html` из модульной версии скриптом `tools/build-standalone.js`:
стили, скрипт и фото встраиваются внутрь, а секции (услуги, работы, стек, этапы)
подставляются в разметку уже отрисованными.

**Страховка от пустой страницы.** Класс `no-js` на `<html>` снимает скрипт. В CSS есть
правило `.no-js .reveal { opacity: 1 }`, поэтому если JavaScript выключен или упал,
страница всё равно покажет весь контент, а не останется пустой.

Если нужен локальный сервер (например, посмотреть с телефона в той же сети):

```powershell
python -m http.server 5500     # затем http://127.0.0.1:5500
```

## Что было сделано для скорости

Первая версия тормозила. Причины и что с ними стало:

| Было | Почему тормозило | Стало |
|---|---|---|
| Шрифты с `fonts.googleapis.com` | внешний запрос блокирует первую отрисовку, без сети — ожидание таймаута | системный стек шрифтов (`Segoe UI`), ноль запросов |
| `backdrop-filter` на 6 больших панелях | размытие фона под элементом пересчитывается на каждом кадре прокрутки | плотные полупрозрачные подложки |
| `filter: brightness(var(--bg-bright))` на фото | полноэкранный фильтр пересчитывался каждый кадр | корректировки запечены в JPEG, яркость — слой `.bg__flash` через `opacity` |
| `filter: blur(34px)` на луче и блике | дорогая растеризация больших слоёв | мягкость даёт сам градиент, без `blur` |
| `mix-blend-mode: screen` на фоне | наложение больших слоёв в композиторе | обычная прозрачность |
| анимация `box-shadow` у пульса | перерисовка каждый кадр | кольцо на `::after` через `transform` + `opacity` |
| анимированный шум на 200% экрана | постоянная перерисовка огромного слоя | статичная текстура |
| 26 пылинок с `box-shadow` | 26 слоёв + тени | 16 пылинок, мягкая точка градиентом |
| бесконечная печать текста в консоли | разметка пересобиралась ~20 раз в секунду вечно | печатается один раз и останавливается |
| бегущая строка крутилась всегда | вечный расход CPU даже вне экрана | пауза, когда строка не видна |
| запись в `style` в каждом кадре | браузер пересчитывал стили впустую | `setStyle()` пишет только изменившееся значение |
| кадры во вкладке-фоне | CPU грелся в фоне | цикл засыпает при `document.hidden` |
| **баг инерционного скролла** | блок синхронизации сравнивал позицию «до» и «после» своего же сдвига и на каждом кадре обнулял цель — один щелчок колеса (115 px) давал всего ~20 px, поэтому прокрутка казалась бесконечной | сравнение идёт с собственным записанным значением (`scroll.written`), щелчок проходит ровно столько, сколько должен |

Итог (замер автотестом на DOM-стабе): один щелчок колеса = 115 px вместо прежних 20 px
(в 5,7 раза быстрее), прокрутка доходит ровно до низа и до верха, а за 150 кадров полного
простоя — **0 записей в DOM**. Во время прокрутки около 4 записей в кадр, и все только
`transform`/`opacity`, то есть работа композитора, а не процессора.

Дополнительно: на слабых машинах (≤ 4 логических ядер или ≤ 4 ГБ памяти) включается
`liteMode` — фон становится статичным, пылинки и блик не создаются.

## Кнопка «эффекты» (внизу справа)

Включает и выключает кастомный курсор, стретч, инерционный скролл и анимации фона.
Это же и «облегчённый режим»: выключил — страница ведёт себя как обычный статичный сайт.
Выбор запоминается в `localStorage`.

Эффекты включены по умолчанию и **не зависят от системной настройки Windows «уменьшить
движение»**. В первой версии они от неё зависели — если в Windows отключены эффекты
анимации, курсор и стретч молча не работали.

## Структура кода

`script.js` — один IIFE, внутри пронумерованные разделы:

```
1  CONFIG        весь контент сайта: имя, контакты, услуги, проекты, стек, этапы
2  Утилиты       $ , $$ , clamp, lerp, setStyle (запись только при изменении)
3  Рендер        отрисовка контента из CONFIG
4  Reveal        появление блоков при прокрутке
5  SmoothScroll  перехват колеса + инерция
6  frame()       единственный requestAnimationFrame на всю страницу
7  Фон           параллакс, пылинки, вспышка от скорости
8  Параллакс     слои hero + 3D-наклон консольной карточки
9  Курсор        круг + кластер точек в центре
10 Мелочи        хедер, меню, spotlight, копирование, печать текста
11 Старт         порядок инициализации
```

`styles.css` — 20 разделов, оглавление в шапке файла. Все анимации построены только на
`transform` и `opacity`; это записано правилом в комментарии в начале файла, чтобы при
правках никто не добавил дорогое свойство.

## Что поменять в первую очередь

Весь контент — в объекте `CONFIG` в начале `script.js`:

```js
name: "HumsterStudio",             // название студии: шапка, hero, футер
status: "Берём новые проекты",     // строка-статус в hero
availability: "Отвечаем в течение дня",
roles: [                           // блок «Кто в команде» в секции «О команде»
  { title: "Frontend", text: "Вёрстка, интерфейсы, анимации, адаптив." },
  { title: "Backend",  text: "Серверная логика, база данных, API и интеграции." },
  { title: "Десктоп",  text: "Программы для Windows: утилиты, окна, работа с файлами." },
  { title: "Дизайн",   text: "Макеты, типографика, иконки и UI-кит." },
  { title: "QA и поддержка", text: "Тесты, приёмка и доработки после релиза." }
],
contacts: {
  email: "you@example.com",        // ← пока заглушка, нужен реальный
  telegram: "@username",           // ← и это тоже
  github: "github.com/username"    // ← и это
},
skills: ["HTML / CSS", "JavaScript", ...]   // список примерный, поправь под себя
```

**Роли.** В `roles` — состав команды. Сейчас там пять ролей без имён: этого достаточно,
чтобы читалось как группа, а не как один человек. Если захочешь указать людей — добавь
в объект поле `name` и выведи его в шаблоне `rolesList` в разделе 3 `script.js`:

```js
{ title: "Frontend", name: "Аня", text: "Вёрстка, интерфейсы, анимации, адаптив." }
```

Добавить или убрать роль — просто поправить массив, разметка подстроится.

Контакты — единственное, что осталось заглушкой: они подставляются и в карточки
внизу, и в кнопку «Скопировать e-mail».

### Как добавить проекты

Правки делаются в `CONFIG` в `script.js` (модульная версия). Если пользуешься
`standalone.html` — там тот же объект `CONFIG` лежит внутри встроенного скрипта,
и готовую разметку карточек тоже стоит поправить (или просто пересобрать файл
из `index.html`).

```js
{
  title: "Магазин мебели",
  text: "Каталог на 900 товаров, фильтры, оплата, админка.",
  tags: ["E-commerce", "Админка"],
  year: "2025",
  url: "https://example.com"   // ← ссылка
}
```

* `url: null` → бейдж **«ссылка скоро»** и подпись «Ссылка появится позже»
  (сейчас так у всех четырёх — работы пришлёшь позже);
* `url: "https://..."` → бейдж **«готово»** и ссылка «Открыть проект ↗»;
* новых карточек можно добавить сколько угодно — сетка подстроится (сейчас она
  на три колонки, поэтому шесть услуг дают ровно две полные строки).

## Контакты

Заданы в `CONFIG.contacts` — двумя полями: `value` (что показывается) и `url` (куда ведёт).
Так не нужно угадывать по строке, ссылка это или ник.

```js
contacts: {
  email:    { value: "humsterstudio@bk.ru",          url: "mailto:humsterstudio@bk.ru" },
  telegram: { value: "@HumsterStudio",                url: "https://t.me/HumsterStudio" },
  github:   { value: "github.com/pheIsn",              url: "https://github.com/pheIsn" }
},
```

Кнопка «Скопировать e-mail» берёт адрес из `contacts.email.value`. Если какая-то карточка
не нужна — убери её из `index.html` (блок `.contact__grid`), остальные подстроятся.

## Анимация слайдов (секций)

Каждая секция «входит» по-своему — чтобы страница читалась как набор экранов, а не
как один длинный текст.

| Секция | Что анимируется |
|---|---|
| Hero | строки заголовка выезжают из маски по очереди (как титры), факты — каскадом, консоль наклоняется за курсором |
| Бегущая строка | едет постоянно, ускоряется от скорости прокрутки, встаёт на паузу вне экрана |
| Услуги | 6 карточек влетают каскадом (подъём + лёгкий масштаб), в каждой сверху прочерчивается линия; при наведении карточка приподнимается и наклоняется за курсором, номер подсвечивается и сдвигается, под курсором идёт блик |
| Работы | то же, плюс световой блик по карточке и уезжающая стрелка |
| О команде | текст выезжает слева, панель «Кто в команде» — справа: роли влетают каскадом (с наклоном за курсором), затем всплывают чипы стека по одному |
| Как мы работаем | шаги влетают по очереди, над каждым прочерчивается линия; при наведении — подъём, наклон и блик под курсором |
| Контакты | карточки появляются каскадом; при наведении проходит блик, стрелка уезжает в угол, а сама карточка тянется за курсором («магнит»). Наклона и масштаба здесь нет — так было задумано |

Плюс у каждой секции своя **полоска прогресса** под номером (`01`…`05`): она
заполняется, пока секция проходит через экран.

### Как устроен наклон карточек

Наклон вешается атрибутом `data-tilt` — в шаблонах `script.js` для услуг, работ, ролей
и шагов, плюс на консольную карточку в hero. Карточки контактов в это не входят: у них
своя анимация наведения (блик, стрелка, «магнит»). Два подворота (по горизонтальной и вертикальной оси)
собираются в **одну ось свойства `rotate`**:

```
rotate: ax ay 0 угол      /* ax, ay — нормализованная ось, угол = длина вектора */
```

`rotate` — независимое свойство CSS, поэтому оно не конфликтует с `transform`, который
используют появление `.reveal` и стретч. Максимальный подворот — `TILT_DEG` в `script.js`
(сейчас 5°). Возврат в ноль плавный: значение ведёт `lerp` в кадре, а когда карточка
встала, свойство снимается совсем — в простое в DOM не пишется ничего.

Ещё нюанс: каскадная задержка появления (`--delay`) через 1,4 с обнуляется — иначе она
тормозила бы и hover-анимации той же карточки.

Разметка маски — три уровня: `.line`/`.mask` (обрезает) → `.reveal--up` (выезжает,
его и наблюдает IntersectionObserver) → `[data-stretch]` (тянется от скорости
прокрутки). Три уровня нужны, чтобы появление и стретч не перебивали `transform`
друг друга.

## Стретч-эффект

Чем быстрее крутишь колесо, тем сильнее тянет:

| Что | Формула | На пределе |
|---|---|---|
| Заголовки и титры hero | `scaleY(1 + abs*0.26) scaleX(1 - abs*0.07) skewY(n*2.4deg)` | выше на 26%, уже на 7%, подкос 2.4° |
| Карточки услуг и работ, шаги, панель стека, консоль | `scaleY(1 + abs*0.08)` | выше на 8% |
| Фон | `scale(1 + abs*0.03, 1 + abs*0.06)` + вспышка `.bg__flash` | — |

`abs` — сглаженная скорость прокрутки (0…1), `n` — она же со знаком: вниз тянет в одну
сторону, вверх — в другую, поэтому подкос меняет направление.

Настраивается в `frame()` в `script.js`:

```js
var n = clamp(scroll.smoothVel / 60, -1, 1);   // делитель = чувствительность
"... scaleY(" + (1 + abs * 0.26) ...           // 0.26 — растяжение заголовков
"... scaleY(" + (1 + abs * 0.08) ...           // 0.08 — мягкое растяжение блоков
```

Кажется резким — уменьши `0.26` до `0.15`; незаметно — подними до `0.35`.

## Тонкая настройка

**Прокрутка** — объект `scroll` в разделе 5:

```js
ease: 0.2,      // пока колесо крутят: доля отставания, которую проходим за кадр
settle: 0.5,    // колесо отпустили (> 90 мс): догоняем быстрее, без «долгого доезда»
gain: 1.15,     // сколько пикселей страницы на один «щелчок» колеса
maxStep: 150,   // предел движения за кадр, чтобы не было рывков
```

Плюс `maxLag = window.innerHeight * 0.7` в обработчике колеса — на сколько пикселей
цель может убежать вперёд. Больше значение → более длинный «доезд» после прокрутки,
меньше → страница следует за колесом жёстче.

**Сила стретча** — в `frame()`:

```js
var n = clamp(scroll.smoothVel / 60, -1, 1);   // делитель = чувствительность
"... scaleY(" + (1 + abs * 0.15) ...           // 0.15 — растяжение по вертикали
"... scaleX(" + (1 - abs * 0.05) ...           // 0.05 — сжатие по горизонтали
```

**Курсор** — раздел 9:

```js
cur.ringX = lerp(cur.ringX, cur.x, 0.16);   // инерция круга
cur.dotX  = lerp(cur.dotX,  cur.x, 0.42);   // инерция центральной точки
var radius = 3.6 + cur.energy * 0.42;       // разлёт точек от скорости
cur.angle += 0.006 + cur.energy * 0.0032;   // скорость вращения кластера
```

Размеры — в `styles.css`: `.cursor__ring` (40px), `.cursor__dot` (5px), `.cursor__sat` (3px).
Число точек = число `<span class="cursor__sat">` в `index.html`.

**Фон — одна картинка.** `assets/bg-main.jpg` медленно дрейфует с лёгким зумом
(40 с, без поворота — в ней есть прямые грани). Поверх неё JS двигает параллакс всей
группы: от прокрутки, от курсора и от скорости. Остальные слои фона — только лёгкие
добавки, второй картинки нет:

| Слой | Что делает |
|---|---|
| `.bg__main` | сама картинка, дрейф 40 с |
| `.bg__particles` | 16 пылинок, всплывают и мерцают |
| `.bg__flash` | слабое свечение при быстрой прокрутке (максимум 32 % прозрачности) |
| `.bg__vignette` | затемнение краёв, чтобы текст читался |

Заменить фон — положи свой файл в `assets/` и поправь путь в `.bg__main`; сборщик
`standalone.html` подставит любые картинки из `assets/` автоматически.

> **При обновлении версии распаковывай архив в чистую папку.** Если распаковать поверх
> старой, прежние картинки останутся лежать рядом (браузер их не подтянет, но в папке
> будет путаница из старых и новых файлов).

**Плавность.** Значения подобраны так, чтобы ничто не «догоняло» с задержкой:

| Что | Значение | Сколько это в кадрах |
|---|---|---|
| Появление блоков | 0.5–0.62 с | ~35 кадров |
| Каскад карточек | 55 мс на карточку | — |
| Наведение (подъём, рамка, блик) | 0.22–0.3 с | ~15 кадров |
| Наклон за курсором | `lerp(..., 0.3)` | ~3 кадра до 90 % |
| Фон за курсором | `lerp(..., 0.12)` | ~18 кадров |
| Круг курсора / точка | `lerp 0.22` / `0.52` | точка почти сразу |
| Прокрутка | `ease 0.24`, `settle 0.55` | щелчок проходит за ~8 кадров |
| Стретч реагирует | `lerp(..., 0.2)` | ~10 кадров |

Если где-то снова покажется «тормозным» — уменьшай длительности переходов в `styles.css`
(секции 12–18) или поднимай коэффициенты `lerp` в `script.js`: чем ближе к 1, тем резче
и отзывчивее.
Формат JPEG/WebP, от 1920 px по ширине; остальное сделают `background-size: cover`
и градиенты.

## Поведение на разных устройствах

* Телефон/планшет: кастомный курсор и перехват колеса отключаются, скролл нативный,
  фон статичный (экономия батареи).
* `prefers-reduced-motion: reduce`: гасятся декоративные анимации фона, рабочие
  эффекты остаются под кнопкой «эффекты».
* Есть `skip-link` для клавиатуры, `noscript`-заглушка и стили для печати.
